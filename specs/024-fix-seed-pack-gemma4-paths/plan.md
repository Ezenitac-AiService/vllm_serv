# Implementation Plan: 코드베이스 전체 모델 경로 하드코딩 제거 및 Gemma 4 카탈로그 정합성 보장

**Branch**: `024-fix-seed-pack-gemma4-paths` | **Date**: 2026-07-30 | **Spec**: [spec.md](file:///home/dev/storage/vllm_serv/specs/024-fix-seed-pack-gemma4-paths/spec.md)

**Input**: Feature specification from `/specs/024-fix-seed-pack-gemma4-paths/spec.md`

## Summary

Seed Pack 이관 및 파이썬 벤치마크/다운로드 스크립트 실행 시 설정 파일(`config/model_catalog.json`) 외부 소스코드(`src/core/config.py`, `src/scripts/*`, `scripts/*`)에 파편화되어 존재하던 하드코딩된 모델 ID (`gemma4-2b` vs `gemma4-e2b` Mismatch), 타겟 디렉토리 경로, 잘못된 HF Repo ID 및 HF 토큰 강제 정책을 전면 제거합니다. `ConfigManager().get_model_catalog()`를 단일 진실 소스(SSOT)로 일원화하고 `config/model_catalog.json` 내 Gemma 4 메타데이터(`gemma4-e2b`, `gemma4-e4b`, `gemma4-12b`)의 `repo_id`, `filename`, `clip_filename`, `target_dir`, `model_path`, `clip_path` 정합성을 정밀 보정하여, 다운로드, 스폰 및 벤치마크 실행 시 경로/404 오류 없이 100% 자동 서빙을 보장합니다.

## Technical Context

**Language/Version**: Python 3.11+

**Primary Dependencies**: `pydantic`, `huggingface_hub`, `httpx`, `pytest`, `fastapi`

**Storage**: Local files (`config/model_catalog.json`, `models/` directory)

**Testing**: `pytest` (`uv run pytest tests/`)

**Target Platform**: Linux GPU Server (Intel i7 930 / NVIDIA GTX 1070 8GB / GTX 1080 Ti 11GB VRAM)

**Project Type**: Python CLI / Async GPU Model Serving Engine

**Performance Goals**: 모델 다운로드/인스턴스 생성 시 0ms overhead, `ConfigManager` 룩업 지연시간 < 1ms, 벤치마크 원스톱 무장애 통과

**Constraints**: `uv` 환경 격리 보장 (`uv run`), 레거시 스크립트 실행 시 404 Not Found 및 파일 경로 누락 오류 0건, `HF_TOKEN` 미설정 시에도 공개 GGUF 모델 다운로드 허용

**Scale/Scope**: 6종 모델 카탈로그 (Gemma 4 3종 + Qwen 3.5 3종), `src/core/`, `src/scripts/`, `scripts/`, `tests/` 전반의 소스코드 리팩토링
