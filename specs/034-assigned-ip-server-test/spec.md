# Feature Specification: Assigned IP Server Verification Test (할당된 IP 기반 서버 구동 검증 테스트)

**Feature Branch**: `034-assigned-ip-server-test`

**Created**: 2026-07-30

**Status**: Draft

**Input**: User description: "서버 구동 확인 테스트 코드에, localhost나 120.0.0.1도 테스트 해야 하지만, 할당받은 ip를 통해서도 접속 되는지, 호출 되는지, 응답하는지 테스트 하는 항목이 있어야 하지 않을까?"

## Clarifications

### Session 2026-07-30

- Q: 듀얼랜(Dual LAN) 등 다중 네트워크 인터페이스 환경에서 할당 IP 테스트 대상 범위 → A: 호스트의 모든 활성 비-루프백(Non-loopback) IP 주소(듀얼랜 포트 2개 포함)를 순회하며 모두 접속/호출/응답 테스트 수행.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Loopback 및 할당 IP 접속 검증 (Priority: P1)

서버 구동 확인 테스트 실행 시 localhost(127.0.0.1) 뿐만 아니라 듀얼랜 포트를 포함하여 네트워크 카드에 실제 할당된 모든 비-루프백 IP 주소를 통하여 서버 엔드포인트에 접속, 호출 및 정상 응답이 수신되는지 검증한다.

**Why this priority**: 외부 클라이언트나 타 시스템에서 해당 서버의 어느 LAN 포트 IP로 접속하더라도 정상 작동함을 보장하는 핵심 기능이므로 가장 높은 우선순위를 갖는다.

**Independent Test**: 서버 구동 후 루프백 IP 및 각 할당 IP(듀얼랜 포함)로 각각 API 호출을 수행하고 정상 응답(HTTP 200)을 반환하는지 독립적으로 검증한다.

**Acceptance Scenarios**:

1. **Given** 서버가 구동 중이고 듀얼랜 등 네트워크 IP가 할당되어 있을 때, **When** 할당된 각각의 비-루프백 IP 주소와 포트로 헬스체크 엔드포인트를 호출하면, **Then** 모든 활성 IP에 대해 HTTP 200 OK 응답과 성공 메시지를 반환한다.
2. **Given** 서버가 0.0.0.0 또는 특정 IP로 바인딩되어 있을 때, **When** localhost(127.0.0.1) 및 모든 할당 IP로 동시/순차 요청을 보내면, **Then** 모든 요청이 정상 처리된다.

---

### User Story 2 - 동적 IP 탐지 및 테스트 바인딩 (Priority: P2)

테스트 실행 시 호스트 환경에 할당된 유효한 비-루프백 IP 주소 목록(듀얼랜 포트 포함)을 자동 탐지하거나 구성된 서버 IP 정보를 가져와 테스트 대상 경로로 설정한다.

**Why this priority**: 하드코딩된 IP 대신 실제 환경의 모든 IP를 동적으로 활용하여 환경 독립적이고 포괄적인 테스트를 제공하기 위함이다.

**Independent Test**: 네트워크 인터페이스에서 할당된 모든 비-루프백 IP를 자동 식별하여 테스트 요청 대상 URL 목록을 생성하고 접속을 시도한다.

**Acceptance Scenarios**:

1. **Given** 듀얼랜 등 유효한 네트워크 인터페이스가 복수 존재하는 환경에서, **When** 테스트 코드가 실행되면, **Then** 호스트의 모든 활성 비-루프백 IP 목록을 자동으로 추출하여 테스트 URL을 구성한다.

---

### User Story 3 - 네트워크 예외 및 바인딩 실패 진단 (Priority: P3)

서버가 특정 외부 IP로 리슨하지 않거나 방화벽/네트워크 문제로 특정 할당 IP 접속이 실패하는 경우 명확한 진단 정보를 제공한다.

**Why this priority**: 테스트 실패 원인이 특정 LAN 포트 바인딩 문제인지 네트워크 차단 문제인지 쉽게 파악할 수 있도록 돕는다.

**Independent Test**: 바인딩이 루프백으로 제한되거나 특정 NIC에만 적용된 상태에서 각 할당 IP 접속을 시도하고 명확한 오류 로그가 기록되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 서버가 127.0.0.1로만 바인딩되거나 특정 LAN 포트만 리슨하는 경우, **When** 미바인딩 할당 IP로 접속 테스트를 수행하면, **Then** 테스트는 명확한 접속 거부(Connection Refused) 원인과 해당 IP 정보를 출력한다.

---

### Edge Cases

- 서버가 0.0.0.0이 아닌 127.0.0.1에만 바인딩되어 외부 IP 접속이 차단되는 경우
- 듀얼랜(Dual LAN) 환경에서 LAN 1번 포트는 성공하나 LAN 2번 포트는 바인딩/네트워크 설정 문제로 접속 불가능한 경우
- 네트워크 카드가 비활성화되어 있거나 루프백 외의 할당 IP가 없는 단독 환경인 경우
- IPv4 및 IPv6가 동시에 존재할 때 접속 테스트 대상 IP 우선순위 처리

## Definition of Done (작업 종료 조건) *(mandatory)*

- **DoD-001**: localhost(127.0.0.1) 및 듀얼랜 포트를 포함한 모든 실제 할당 IP 주소를 통한 서버 접속, 호출, 응답 검증 테스트 케이스 작성 완료
- **DoD-002**: `uv run pytest` 실행 시 할당 IP 기반 서버 구동 검증 테스트가 기존 테스트 suite와 함께 정상 통과
- **DoD-003**: 특정 IP 바인딩 실패 또는 네트워크 접근 불가 시 명확한 오류 진단 로그 제공 검증

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 테스트 시스템은 서버 구동 검증 시 localhost/127.0.0.1 검증 외에도 듀얼랜 포트를 포함한 호스트의 모든 활성 비-루프백(Non-loopback) IP 주소를 순회하여 접속/호출/응답을 검증해야 한다.
- **FR-002**: 테스트 시스템은 각 할당 IP 주소로 엔드포인트 호출을 수행하고 정상적인 200 OK 응답 데이터를 수신하는지 검증해야 한다.
- **FR-003**: 테스트 시스템은 호스트의 유효한 모든 비-루프백 IP 주소 목록(듀얼랜 포트 IP 포함)을 동적으로 추출하거나 구성 정보를 참조하여 개별 IP별 테스트 대상을 지정해야 한다.
- **FR-004**: 할당 IP를 통한 접속 실패 시, 테스트 결과 리포트에 접속 실패 원인(바인딩 미설정, 타임아웃 등) 및 실패한 특정 IP 주소를 구체적으로 표시해야 한다.

### Key Entities

- **Server Network Context**: 테스트 대상 IP 목록(루프백 및 듀얼랜 할당 IP들), 포트 번호, 바인딩 상태 및 엔드포인트 URL 정보를 보유하는 엔티티.
- **IP Test Verdict**: 각 IP별 접속 테스트 결과, 응답 시간, HTTP 상태 코드, 오류 상세 내역을 담는 검증 엔티티.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 서버 구동 검증 테스트 집합 실행 시 localhost 및 모든 할당 IP(듀얼랜 포함) 테스트가 100% 자동 포함 및 수행된다.
- **SC-002**: 할당 IP 기반 서버 접속 검증 테스트가 개별 IP당 3초 이내에 성공/실패 여부를 판정한다.
- **SC-003**: IP 미할당 또는 특정 포트 바인딩 오류 발생 시 원인을 정확히 식별 가능한 테스트 진단 메시지를 100% 제공한다.

## Assumptions

- 테스트 대상 서버는 0.0.0.0 또는 모든 할당된 호스트 IP 인터페이스로 리슨하도록 설정 가능하거나 설정되어 있다.
- 실행 호스트 환경에는 듀얼랜 포트 등 유효한 네트워크 IP 주소가 할당되어 있다.
- 본 프로젝트의 테스트 표준에 따라 모든 검증은 `uv run pytest` 환경에서 수행된다.
